Maths Practice V4.2 — Database Migration Statement

Stable V4.2 application release merge:
3a9a4cb90e8b3dd0b26ed27766508e9037d3e347

V4.2 DOES include additive Supabase database changes.

These migrations were already applied and tested during the staged V4.2B/V4.2C rollout before the final V4.2 release freeze:

1. supabase/v42b_practice_assignments.sql
   - creates the dedicated targeted Practice Assignment model;
   - creates teacher-managed practice assignment records and student attempt records;
   - adds secure student list/start/complete RPCs;
   - keeps assignment completion server-validated.

2. supabase/v42b_practice_assignment_target_snapshot.sql
   - snapshots the actual required question target when a student starts/restarts an assignment attempt;
   - prevents the completion target from moving if question-bank availability changes later.

3. supabase/v42c_safe_roster_student_delete.sql
   - adds the guarded teacher-only unused-roster deletion RPC;
   - blocks permanent deletion when learning/history records exist;
   - permits cleanup of truly unused mistaken roster records after server recheck.

V4.2A Teacher Action Center: no SQL migration.
V4.2D Quick Add Student: no SQL migration.
V4.2E Release Polish: no SQL migration.

Release instruction:
- Do NOT re-run the three migrations solely because V4.2 is deployed or because release documentation is updated.
- The frozen V4.2 release assumes the production database already contains the tested V4.2B/V4.2C changes.
- Preserve existing RLS, student-access, grading, Exam, answer-release and AI-security boundaries.

Rollback instruction:
- A routine application rollback to V4.1 does NOT require dropping the additive V4.2 tables/functions.
- Do not drop Practice Assignment tables or related functions as part of an app rollback; that could destroy V4.2 assignment data.
- Any future database removal must be a separate, explicit migration with backup/data-preservation planning.
